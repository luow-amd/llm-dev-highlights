### 🛠️ 重点技术变更

1. **#63401 — ROCm 可扩展 KV cache 按精确显存核算（已合并）**
   amdgpu 驱动在 `hipMemGetInfo` 中对每次分配做 2MB 向上取整（设计如此，见 `drm/amdgpu` commit `1ac354beecfd`），warmup 期加载的大量 kernel code object 使"空闲显存"被系统性低估数 GB。本 PR 用 sysfs `mem_info_vram_used` 在最终 sizing 时**只回补一次**，且保证不超过物理空闲、不补其他进程分配。对 R9700 这类 32GB 显存卡，KV cache token 数提升约 47%，是**投入产出比最高的 AMD 修复之一**。

2. **#62675 — Qwen4Exp PLE n-gram 的 piecewise graph 状态污染修复（已合并）**
   这不是性能问题而是**服务历史依赖**的正确性问题：回放读取 `query_start_loc`/`ngram_context` 的陈旧尾部，hashed 出错误 n-gram。修复方式是按 graph capture 时的请求数填充两个 buffer。77/300 → 0/300 的对比数据说明**PIECEWISE CUDA graph + 请求级 Python 状态**是一个需要系统性审计的组合，类似问题可能在其他模型状态（PLE、Per-Layer Embedding、engram）上复现。

3. **#51006 — Fused MoE 路由插件化（已合并）**
   将 `FusedMoERouter` 改为 `PluggableLayer`，复用 `MoERunner`/`RoutedExperts` 已有的 OOT 类注册机制，**不引入 Platform hooks 或第二套 registry**。保留显式 router 实例、模型特定构造器/权重加载器、expert substitution 与可选 EPLB state。对希望注入自定义路由（如 AMD Hyperloom 的 grouped_topk 优化 #66458 之外的定制）的下游项目是长期扩展点。

4. **#66491 — RDNA4 packed-weight INT4 GEMM RFC（Issue，开放讨论）**
   与现有 `RDNAHybridW4A16LinearKernel` 的"直接读 GPTQ/AWQ 布局"不同，该方案**加载时重打包为 WMMA fragment order + scales/zp 交织**，用一个 HIP kernel family 覆盖 1–448 tokens，超过则反量化到 packed BF16 prefill GEMM。在 R9700 250W、ROCm 7.2.1 上给出 1.12×–1.84× 的 decode 加速。**关键不确定性是上游编排**：作者明确要与 #62708（INT4 lm_head）、#63562（gfx12 Triton tile）协调，避免冲突。若被接受，将成为 RDNA4 上 W4A16/W4A8 的默认快路径候选。

5. **#65227 — Encoder CUDA graph：每批一次 replay + 统一 budget grid（已合并）**
   原实现把 batch 贪心拆成多次 padded replay，大 batch 反而比 eager 慢。新规则：**每批只 replay 最小可容纳 budget，超出则整批 eager；`encoder_cudagraph_max_token_budget` 默认 5120（仿 LLM 的 max capture size）**。GB200 上 7 个模型 encoder latency 1.14–1.32×；MiniMax-M3 / MI355X TP2 上 encoder graph 显存 16.9 → 5.7 GiB per rank，带来 +8% KV cache tokens。**注意默认值有已知取舍**：Gemma 4 与 >5120 token 的大 batch 走 eager，文档已记录。

### 💡 值得关注的问题

1. **#66422 多模态缓存投毒（安全，高优先级）**：`ProcessorInputs.get_mm_hashes()` 把内容寻址 digest 与调用方自选 `uuid` 放入**同一无标签键空间**，未授权调用方可提交 token 数匹配的异构媒体并设置 `uuid=H` 污染 `MultiModalProcessorCache` 与 `EncoderCacheManager`；`cache_salt` 仅进入 prefix-cache 块哈希，**不阻止多模态/encoder 缓存别名**。两缓存默认开启，无需 opt-in。已有贡献者 Kylinny 认领。**这是本周期最严重的安全类 Issue，建议尽快给出修复与 CVE/公告评估。**
