### 💬 高热度讨论分析

剔除 CI 机器人评论后，较有实质讨论的热点如下：

1. **#60934 `[RL] Support per-parameter source layouts for NCCL M2N`（已合并）**  
   - 核心议题：让每个逻辑参数声明自己的 trainer 侧 source mesh/placements，从而在同一 NCCL M2N 会话中支持 dense 参数 `(DP, TP)` 与 expert 参数 `(EDP, EP)` 等混合布局。  
   - 观点：`hao-aaron` 认可方向，但主张把 NCCL runtime identity、`NCCL_RESHARD_*` 环境变量一致性、poisoning 状态机等库特定逻辑移回 `nccl_m2n`/`nccl-extensions`；`pkousha` 随后移除永久 poisoning 和部分生命周期状态机，改用 nccl4py。  
   - 争议/风险：`hao-aaron` 指出 uneven source shards 可能从“初始化报错”退化为“首次更新挂起”；CI 中 `importorskip("nccl.m2n")` 导致真实通信与字节搬运路径未被覆盖。  
   - 状态：已合并，但 CI 镜像与真实传输测试被明确列为后续基础设施工作。

2. **#59413 `[Bug][ROCm] GLM-5.3-Flash gibberish at low concurrency`（已关闭）**  
   - 核心议题：MI350/MI300、TP8、`ROCM_AITER_MLA_SPARSE` 下低并发乱码，高并发反而较正常。  
   - 观点：报告者给出 GSM8K 与 greedy 复现；`vllmellm` 复现并发现 `VLLM_ROCM_USE_AITER_MOE=0` 可恢复；`simondanielsson` 定位到 ROCm/aiter#5979，并用打补丁 nightly 验证修复。  
   - 结论：问题根因在 AITER 上游，vLLM 侧通过升级/打补丁解决。该讨论凸显 AMD 软件栈跨仓库协同的重要性。

3. **#59824 `[ROCm][Kimi-K3] DSpark adaptive verification on MI355X`（已合并）**  
   - 核心议题：在 ROCm 上启用 Kimi-K3 adaptive verification，需要同时解决 zero-draft 投机步的 GDN 状态保持、TP rank 间 adaptive 决策同步、varlen query 上界等问题。  
   - 观点：`DimensionSTP` 请求先合入 #55504 的 query-width bound，并说明 H100/CUDA 测试结果；`okorzh-amd` 确认 E2E 可用；`dllehr-amd` 参与 CI 路由。  
   - 争议点：依赖 PR 的合入顺序与 backport 清理；最终本 PR 已合并，体现 AMD 投机解码能力在向 NVIDIA 对齐。

4. **#60544 `[Feature][MoRIIO] Support hybrid WRITE transfers with DSpark`（已合并）**  
   - 核心议题：为 hybrid attention/Mamba/KDA 模型启用 MoRIIO WRITE，并处理 DSpark 的最终 prefill 状态、投机 scratch slot 排除与 N-1 token 计数。  
   - 观点：`tjtanaa` 主动提出协助 review/push fix，并补充单测以加速合入；作者接受协作。讨论不激烈，但体现了 MoRI/KV connector 方向需要跨团队测试。  
   - 状态：已合并，GSM8K 与单元测试覆盖被记录。

5. **#61993 `[Feature][Quantization] Add online Hadamard rotations before RMSNorm`（开放）**

### 🛠️ 重点技术变更

1. **#59824 ROCm Kimi-K3 DSpark adaptive verification（已合并）**  
   技术点：移除 `supports_device_cpu_query_lens_mismatch` 限制，为 ROCm KDA 与 AITER MLA 声明 varlen 上界，并在 TP rank 间同步 adaptive 决策，避免不同 rank 选择不同 draft budget 导致 collective 不匹配。影响：AMD 平台首次较完整地支持 Kimi-K3 自适应投机验证，对长上下文、高并发 decode 有直接价值。

2. **#52831 ROCm AITER per-tensor quant + RMSNorm 融合（已合并）**  
   技术点：将 `rms_norm`/`fused_add_rms_norm` 与 per-tensor FP8 quant 融合为 AITER 算子，匹配 vLLM IR；在 Llama-3.1-8B FP8-KV、MI 平台测得 +4.9% 吞吐、-4.5% TPOT。影响：ROCm `torch.compile` 融合链路进一步成熟，减少独立量化 kernel 启动与访存。

3. **#61967 + #61968 gfx942 稀疏 MLA decode 双路径优化（开放）**  
   技术点：#61967 为 64+ decode tokens 提供 HIP 内核，K 常驻寄存器、V 走 LDS，split-K + reduce；#61968 为小步长保留 Triton 路径并改用 `BLOCK_K=16` + 2-stage pipelining。影响：针对 MI300X 的 LDS 容量与延迟瓶颈做精细化分工，提升 DeepSeek-V4.1 在 gfx942 上的 decode 效率。

4. **#59857 DeepSeek-V4.1-Flash Prefill Context Parallelism（已合并）**  
   技术点：在 Model Runner V2 + FlashMLA sparse 上支持 PCP，保持 compressed KV、indexer、SWA、Engram lookback、MoE routing 输入与 padding 跨 PCP rank 一致，并处理 ratio-2 跨 chunk 的 predecessor rows。影响：提升长上下文 prefill 并行能力；当前仅 NVIDIA CUDA、单实例 colocated，不支持 P/D 与 KV connector。

5. **#60934 NCCL M2N 按参数源布局（已合并）**  
   技术点：为每个逻辑参数发布全局 shape、dtype、source mesh、placements，使同一 M2N 会话可混合 `(DP, TP)` dense 参数与 `(EDP, EP)` expert 参数。影响：面向 RL/权重热更新场景，减少 gather/normalize；但 uneven shard 与真实通信 CI 覆盖仍是后续风险。
