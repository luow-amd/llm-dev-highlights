### 💬 高热度讨论分析

#### 1. Issue #42317: [Bug]: Prefix cache align-mode 0% cache hit rate for Qwen3.6-35B-A3B

- **核心议题**：用户 `QilaiZhang` 报告在使用 `--mamba-cache-mode align` 时，Prefix Cache命中率为0%，而 `all-mode` 虽有命中但吞吐量甚至低于不使用Prefix Cache。怀疑与 `max-concurrency=1` 有关。
- **观点整理**：
  - `tdoublep`：建议尝试PR #37898，该PR旨在改善对齐模式的缓存命中率。同时指出 `all-mode` 当前可能尚未进入main分支。
  - `s3woz`：解释在 `align-mode` 下，若`max-num-batched-tokens` 足够大且并发低，不会触发分块，也就不会在中间位置创建缓存条目，导致命中率为0。
  - `QilaiZhang`：确认当增加并发数后，命中率不再为零但仍较低。
- **结论**：问题尚未修复，用户将尝试PR #37898。核心是`align-mode`的缓存条目创建机制与`chunked prefill`交互不佳。

#### 2. Issue #42303: [Bug]: `prompt_token_ids` dropped in `EmbedsInput` pipeline

- **核心议题**：`EmbedsInput` 类缺少 `prompt_token_ids` 字段，导致在DFlash投机解码中，backup_next_token_ids等关键状态被破坏，产生乱码输出。
- **观点整理**：
  - `KrxGu`：指出该问题已在PR #40720中修复（增加了 `prompt_token_ids` 支持），但仅存在于main分支，v0.20.1稳定版尚未包含。
  - `abinggo`：最初表示愿意修复，但在获知 #40720 已存在后，认为只需将此修复反向移植到稳定版。
- **结论**：问题根源已定位，修复方案已存在，社区等待维护者决定是否进行反向移植。

#### 3. PR #42300: [Bugfix] Fix Gemma4 streaming tool calls with accumulated parser state

- **核心议题**：对Gemma4的流式工具调用解析器进行全面重构，改用累加缓冲区+结构化差异的方法，解决流式输出中由于分片导致的部分值（float尾部、bool/null、指数符号、MTP token id缺失）损坏问题。
- **多方观点（激烈）**：
  - `bevenky` (PR作者)：主张系统性重写，覆盖多种不稳定分片情况（`.`, `1e`, `tru`, `nu`, `fals`等），并修复MTP/speculative路径的文本修复。
  - `abinggo`：最初认为自己的小范围修复 (#42128) 已被此PR覆盖，表示愿意关闭自己的PR，但后来在`bbrowning`提出担忧后重新开放了 #42128 作为渐进式替代方案。
  - `bbrowning` (审阅者)：强烈倾向于 **小型增量修复** 而非一次性大规模重写，担忧重写带来的风险，询问是否有真实world评估数据。
  - `whytem`：建议将独立的解析器加固片段（指数解析、部分字符串修剪等）拆分为独立PR，避免将可分离的修复与大规模架构变更捆绑。
- **争议焦点**：**架构选择 vs 增量修复**。`#42006`, `#42128`, `#42237`, `#42300` 四个PR在修复同一类问题但策略不同，社区需要时间比较并选择。
- **当前状态**：PR #42300 和 #42128 均保持开放，等待维护者方向性决策。

#### 4. Issue #42273: [Bug]: SWA eviction leaves stale block table entries

- **核心议题**：在滑动窗口注意力(SWA)驱逐后，GPU侧的block table可能残留指向已释放物理块的陈旧条目。这可能导致注意力后端读取到错误数据。
- **观点整理**：
  - `jongukc` (报告者)：发现这一潜在健壮性问题，但不确定是否为有意设计（即允许陈旧条目存在，后端通过mask排除）。
  - `AbhiOnGithub` (PR #42276作者)：认为应明确重写worker block table以保持一致性，并提交了修复PR。他在评论中表示“保守做法是显式重写，而不是依赖每个后端完美mask”。
  - `jongukc`：认可该修复方案。
- **结论**：已提交修复PR #42276，通过监控请求的SWA驱逐并将完整block table发送到worker来解决问题。

### 🛠️ 重点技术变更

1. **[[ROCm][MLA] FP8 ASM prefill + sparse MLA decode (#42294)]**：由AMD工程师 `maeehart` 提交的重量级PR。不仅带来了FP8 ASM预填充的40%+吞吐提升，还实现了基于AITER的持久化稀疏MLA解码，并通过索引器修复保证了正确性。此PR是AMD平台上DeepSeek-V3.2推理性能的重要里程碑。

2. **[[DSv4] Improved dequant gather K cache kernel (#42236)]**：`gau-nernst` 使用CuteDSL重写了DeepSeek V4的 `dequantize_and_gather_k_cache()` 内核，通过多级流水线和 `cp.async` 大幅提高带宽利用率。在长序列K length（如32K）上实现了高达95倍的加速（从微基准看），对DSV4的prefill性能有显著贡献。

3. **[[MoE Refactor] Move remaining experts classes to experts directory (#42334)]**：由 `bnellnm` 主导的MoE模块重构延续。此PR将剩余的experts子类移动到独立的 `experts/` 目录，完成了解耦。上一步重构 (#41979) 遗留的陈旧路径导入问题，已由 #42373 紧急修复。

4. **[[Core][Feat] Pluggable KVCacheConfigBuilder (#42309)]**：`ivanium` 提出了可插拔的KV Cache配置构建器，允许平台或模型覆盖KV缓存规划。通过 `Platform` 扩展点、模型声明字段和默认构建器三层解析，使得在不修改核心代码的情况下实现不同的缓存策略（如CPU Offload、DP等）成为可能。这一设计增强了vLLM的扩展性。

5. **[[Perf] Batch invariance with Cutlass fp8 support, 28.9% E2E latency improvement (#40408)]**：`yewentao256` 使用Cutlass FP8内核实现了批次不变性（batch invariance），避免了量化和反量化的额外开销。在Qwen3-1.7B的推理测试中，端到端延迟降低了28.9%，是性能优化的重要成果。
