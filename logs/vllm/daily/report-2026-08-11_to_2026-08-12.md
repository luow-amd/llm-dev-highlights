### 🛠️ 重点技术变更

**1. [#51837] ROCm KV-first attention blocks 独立 page（已合并）**
混合模型共享 page pool 的隐含前提"block b 占据 page b"在 ROCm 的 `(2, num_blocks, ...)` KV 布局下被打破——K 和 V 分居分配两半，block 实际占用半个 page，导致 Mamba state 与 attention KV 互相踩踏。修复通过 page-first view + 维度交换，保持逻辑 shape 不变，仅对 KV-first attention + Mamba 共享分配的 layer 生效。**影响**：消除了 MI300 上 DSpark 的静默 NaN 损坏，GSM8K 从 0.20 恢复至 0.80+。此类"布局假设被打破"的 bug 极难排查，值得在后续 KV 布局重构中建立不变量断言。

**2. [#51768] DeepSeek V4 MRV1 PIECEWISE CUDA graph 防护（已合并）**
#51430 暴露了 legacy V1 runner 的 breakable PIECEWISE 图路径输出损坏（GSM8K 0.95 → 0.03）。WoosukKwon 选择默认切换到 MRV2 并在 MRV1 + PIECEWISE 组合上 fail-closed，而非 revert #51430。1,319 题 GSM8K 验证 MRV2 保持 0.950，MTP 接受率 81%。**影响**：确立了 MRV2 作为 DeepSeek V4 默认路径，同时保留 MRV1 在 eager/无 PIECEWISE 场景的可用性。对"已知 bug 的 fail-fast 优于静默损坏"做了很好的示范。

**3. [#51803] Kimi-K3 DSpark draft MLA decode kernel for gfx950**
将非因果多-token block 折叠为单个 workgroup tile：所有 `query_len × num_heads` 行共享一个 128-row tile，KV span 只读一次。相比 main 的 flatten + `repeat_interleave` 路径，KV 读取降至 1/query_len，生产 shape 8.45x 加速；其中 3.2x 可通过 Triton 折叠获得，2.62x 来自 fp8 mfma + 单趟 KV + 固定 accumulator frame。`rel_l2=5.3e-3`（cosine 0.999986）。**影响**：为 DSpark 在 gfx950 上的低延迟场景提供了数量级改善，但该 PR 已关闭，需关注后续替代方案。

**4. [#51473] DeepSeek-V4 原生 MXFP4 TP8 分片（已合并）**
ROCm 通用 MXFP4 路径将每 rank 中间宽度从原生 384 对齐到 512（物理 padding），浪费 33% 路由专家显存。修复后将对齐规则旁置到 AITER BF16/SiLU 的 128 对齐契约上，384 不再被抬高。实测每 rank 节省 31.25 GiB 模型内存、KV token 容量 +82.76%，且与 checkpoint header 预测仅差 0.61%。**影响**：对 gfx950 上 DSV4 的 KV 容量是质的提升，尤其有利于长上下文和 agentic 工作负载。

**5. [#46849] AR 投机解码融合多步 CUDA 图（已合并）**
将 post-prefill draft loop 捕获为单个 CUDA graph：attention metadata 构建一次，backend-owned 步间元数据在 graph 内原位刷新，消除逐 step 的 Python 调度和图重放。设计上通过 `supports_update_seq_lens` capability 检测所有 attention 后端，不满足条件时自动降级为逐 step 图。**影响**：长链投机解码的 host 开销从 O(N) 降至 O(1)，是 MRV2 投机解码性能的重要基石。

3. **安全加固 PR 积压**：Trail of Bits 的 8 个安全 PR 覆盖音频、多模态、RealTime、共享内存等多个攻击面，建议 maintainer 优先安排审查合并，避免安全修复长期滞留在 open 状态。

4. **FlexAttention 移除对下游的影响（#50324）**：torchtitan 依赖 vLLM FlexAttention 做 RL generator，移除前需要给出明确的替换路径（TritonAttention 的接口兼容性验证、vLLM 版本迁移指南），否则会破坏 RL 训练链路。

5. **DeepSeek V4 的 MRV1 PIECEWISE fail-closed 策略（#51768）**：默认 MRV2 是正确的，但 MRV1 + `FULL_AND_PIECEWISE` 组合的 fail-fast 是否会影响现有用户的自动化脚本（如依赖 PIECEWISE 图降低延迟的部署），需要关注用户反馈。

6. **ROCm TRITON_MLA + fp8 KV 的 DSpark 路径刚打通（#51860）**：该 PR 仍待合并，合并后应尽快补齐 CI 覆盖（gfx950 x8 TP8 验证已做，但尚缺自动化），防止后续回归。
