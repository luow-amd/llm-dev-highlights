### 💬 高热度讨论分析

#### 1. Issue #54300：GLM-5.3 DCP 崩溃回归（0.27→0.28）

**核心议题**：`GlmMoeDsaForCausalLM`（DSA 稀疏注意力）在 `--decode-context-parallel-size > 1` 时启动即崩溃：`'FlashInferMLASparseMetadata' object has no attribute 'decode'`。Reporter 做了非常严谨的隔离实验（5 个变体 × 2 个 runner × 2 个 cudagraph 模式），证明与 spec decode、runner、cudagraph 模式均无关。

**观点**：
- **reporter（aaronelkins）**：根因是 `FlashInferMLASparseMetadata` 未实现统一 MLA 元数据接口（`.decode`），DCP 分支在首个 decode 形状的 batch 触发。同时澄清自动 rocm 标签错误（实际是 NVIDIA B200/CUDA 13）。
- **cjackal**：main 上已被 #52377 修复，询问 0.28.1 能否 cherry-pick。
- **bandham-manikanta**：正在 A100 多卡上复现调查。

**现状**：Open，等待 0.28.1 修复发布。

#### 2. Issue #54173：Qwen3.8-Flash-Next 在 GB10（sm_121）上 prefix caching + IMA

**核心议题**：`--enable-prefix-caching` 时 `CUBLAS_STATUS_INTERNAL_ERROR` → illegal memory access。触发条件并非重复 prompt，而是**共享前缀但长度不同的多轮对话**。

**观点**：
- **reporter（brainatworkharris）**：经过大量复现后给出确定性结论——#48375 + #53142 修复可完全解决，且是在不同 checkpoint/镜像上交叉验证的。
- **zebgop-ops**：从另一角度补充了**静默变体**：sm_80（3×GA100，PP=3+MTP）上无 IMA，但请求陷入恒定 token 循环。根因定位为 Mamba spec-decode GPU context 捕获了指向逐 step gathered block table 的裸指针，非最后 PP rank 的延迟 postprocess 用过期 batch mapping 遍历当前表，导致反复制/错误复制 recurrent state。修复方案是捕获 per-request-slot 的源 block table 并按 `req_idx` 索引行。

**现状**：Open。两条线（崩溃变体 + 静默变体）指向同一缺陷族——混合模型在 prefix caching + spec decode + 流水线并行下的状态管理问题。

#### 3. PR #54204：engine liveness monitor 误杀健康 EngineCore

**核心议题**：修复 #54184。`connection.wait` 在 Linux 上将 `POLLNVAL/POLLERR/POLLHUP` 映射为读就绪，导致陈旧 sentinel 描述符被判定为进程死亡，无条件 `shutdown()` 撕掉所有健康 EngineCore。

**观点**：
- **antonyamal-3-6-9（reviewer）**：认可 exitcode 判活修复，但指出新引入的 `time.sleep(0.1)` backoff 有隐患——若 sentinel 永久失效，monitor 将以 10Hz 频率空转，建议将受损 sentinel 移出 wait 集合并放入 fallback 轮询列表。
- **作者（afonsojanu）**：采纳建议，将受损 sentinel 移入独立轮询列表，并新增测试验证"永不 resolved 的 sentinel + 健康进程真实退出"场景。

**现状**：Open（待合入）。此修复对多进程部署稳定性至关重要。

#### 4. Issue #54237：0.28.0 启动耗尽全部主机内存

**核心议题**：0.28.0 启动时 vLLM 进程消费 100% 主机内存（48GB）直至 OOM，0.27.1 仅需 12GB。现象涉及大量 `cicc`（NVVM 编译器）进程并行编译。

**观点**：
- **deuch（reporter）**：0.28.1.rc1 看似修复了启动问题，但 benchmark 中仍出现 0.27.x 没有的 OOM；且 nightly 同样复现，排除版本偶然性。使用 `VLLM_HAS_FLASHINFER_CUBIN=1` 时触发 flashinfer cubin 编译风暴。
- **frenzybiscuit**：建议回退到特定 commit 规避。

**现状**：Open。与 flashinfer CUBIN 预编译/编译缓存机制相关，影响生产环境部署决策。

#### 5. Issue #39010（本周期关闭）：ROCm CUDA Graph 捕获挂起

**核心议题**：v0.19.0 起 ROCm 上 CUDA graph 捕获卡在 71%。虽为 4 月 issue，本周期因 stale 自动关闭，但讨论中**反映了 AMD 社区的积怨**。

### 🛠️ 重点技术变更

**1. #53097：启用 block-quantized FP8 融合共享专家**
- 填补 `is_shared_expert_quant_fse_compatible` 对 `Fp8Config` 的空白。通过三道闸门精确放行：`store_dtype != "mxfp4"`（防止存储格式混用）、`weight_block_size is not None`（拒绝 per-tensor 量化）、MTP 部署检测（FSE 与 MTP 不兼容）。
- **影响**：DeepSeek-R1-0528 等 block-FP8 checkpoint 在 ROCm 上恢复融合路径，避免共享专家回退为独立 linear 的性能损失。与 #54206（Quark MXFP4 FSE 误禁用）形成对照，显示 FSE 兼容性是当前 ROCm 优化的关键卡点。

**2. #52047：混合 KV cache 分组路径上的 draft group 标注**
- 修复 `is_eagle_group` 仅由 `_annotate_eagle_groups_deepseek_v4` 写入、Kimi-K3 走通用路径时无标注的架构缺陷。draft group 未标注时消费者将**所有组**视为 draft 组，对 Mamba 组叠加 `required_window += 1` 导致滑动窗口命中条件（连续两块存储）永远无法满足。
- **影响**：外部前缀缓存 + CPU offload 在混合模型上"只写不读"的静默失效问题得以修复，对长上下文 + 多级缓存架构部署至关重要。

**3. #54277：FlashInfer MLA 支持 DCP + DSpark 投机解码**
- 三个关键修复：draft 注意力从自身全局 seq_lens 重算 rank-local 长度（复用 target 长度不充分）；非因果 DCP batch 展开时全局因果边界重复；cache-group 合并要求 `non_causal_multi_token_decode` 一致（原 `any()` 会错误提升因果组）。
- **影响**：DCP 场景下 MTP/EAGLE/DFlash/DSpark 共享元数据管道的统一，消除 DFlash 重复准备逻辑，B300 上 12 个专项测试通过。

**4. #54247：wvSplitKrc 静态 workspace 预分配**
- 修复 MI350X 上 261 GiB 显存驻留：懒分配导致 workspace 落在共享 KV buffer 的 rounding tail，整个 segment 在 shutdown 时被 pin 住。同时将 #53698 的 KV 页填充改为 ROCm-only，避免破坏 NIXL 等依赖 `storage.nbytes()` 精确匹配的后端。
- **影响**：AMD 平台上长生命周期服务的显存释放可靠性问题，与 #54162（MRV2 shutdown 泄漏）共同构成显存生命周期治理的补全。

**5. #54162：MRV2 进程内 shutdown 的引用释放**
- 识别两个 module 级持有者：`_language_model_by_module` 强引用 dict 和 `weakref.finalize` 的实例参数。前者改为 `WeakKeyDictionary`，后者通过 `args=(model,)` 避免 finalize 隐式持有 model。
- **影响**：`VLLM_ENABLE_V1_MULTIPROCESSING=0` 模式下 AMD CI 的 `Memory not free` 失败率归零，为 MRV2 在更多平台上默认启用扫除障碍。

3. **#54206 Quark FSE 误禁用**：虽仅影响性能不影响正确性，但在 Quark 量化模型日益普及的背景下，FSE 的静默关闭会让用户无法感知性能损失。关联 PR #53248/#53097 的合入节奏是关键。

4. **#54308 fp32 SSM cache 溢出**：暴露了混合线性注意力 kernel 对 dtype 组合的健壮性问题——Triton 路径应主动拒绝或正确处理激活 dtype != state dtype 的读游场景。

5. **#54304 量化 embedding 支持**：llm-compressor 已支持 embedding 量化，但 vLLM 多种模型架构无法加载 `weight_packed` 参数。这是量化生态闭环的缺口，bandham-manikanta 表示可能接手。

6. **#54243 torch.compile 下 batch-invariant M buckets 失效**：M 依赖的查表在 Dynamo tracing 时被折叠为常量，导致 decode/prefill 共享同一 tile 配置。Batch Invariance 特性在编译路径下名存实亡，需要设计 tracing 友好的查表方案。
