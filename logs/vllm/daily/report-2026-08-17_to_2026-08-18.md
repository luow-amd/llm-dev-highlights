#### 4. Issue #52617 — LMCache P/D 全命中但解码从 token 0 即分歧（2 条评论）

**核心议题**：LMCache prefill/decode 分离在"远程 KV 传输成功、完整命中"的表象下产出错误结果，是典型的静默正确性失败。9/9 次复现，而原生 NIXL 和 Mooncake 均通过一致性测试。

**关键分析**：**lxy-alexander** 快速定位为 LMCache adapter 的 token 计数不一致：scheduler 在完整命中时减 1 个 token，期望 `need_to_allocate = 894`（最后一个 token 本地重算），但 worker 仍按 `lmcache_cached_tokens = 895` 获取 `tokens[:895]`，导致 decode KV/position 状态不一致。并主动认领修复 PR。

**影响**：该 issue 揭示了 LMCache 集成层在"边界条件"（全命中时的 -1 逻辑）上的脆弱性，也是 P/D 分离架构从"能跑通"走向"可验证正确"的必经问题。

#### 5. Issue #52644 — DeepSeek V4 MRV2 + FULL_DECODE_ONLY 精度问题（3 条评论）

**核心议题**：ROCm MI350/MI355 上，`FULL_DECODE_ONLY` 图模式相比 eager/PIECEWISE 出现明显精度下降（GSM8K 评测可观测）。

### 🛠️ 重点技术变更

#### 1. PR #51208（已合并）— LMCache 随 ROCm 镜像发布
**技术解读**：CUDA 镜像早已支持 `INSTALL_KV_CONNECTORS`，ROCm 镜像却一直缺失。本 PR 采用"发布 wheel 优先 + 源码编译回退"双路径：优先下载 LMCache 官方 GitHub Release 的 ROCm wheel（`--no-index` 防止 pip 静默回退到 PyPI 的 CUDA wheel），架构集合不匹配时则以 `BUILD_WITH_HIP=1` 源码构建。gfx90a（MI200）因 LMCache 无 ROCm wheel 被显式排除而非"静默不覆盖"。
**影响**：ROCm 用户无需手动编译即可体验 LMCache KV 连接器，补齐了与 CUDA 镜像的生态位差距。评审中对 `PYTHONHASHSEED=0` 的讨论也促成了多租户缓存隔离的最佳实践注释。

#### 2. PR #52606 — Kimi-K3 KDA prefill 融合内核
**技术解读**：将 9 个 Triton kernel 的 KDA prefill chunk 流水线融合为两阶段：prologue 并行处理各 64-token chunk（归一化、cumsum gate、Aqk 构建、Akk 求逆、w/u 计算），chunk recurrence 采用两遍扫描（零状态前进记录变换 → 跨组 scan 恢复真实初态 → 从正确起点重走）以提升序列内并行度。
**数据**：单 token 场景 16384 tokens 时 3.50x 加速，E2E TTFT 降低 ~4%。
**影响**：KDA（线性注意力）在长 prefill 下从"kernel 数量多但并行度受限"变为"融合 + 两遍扫描"，为 HBM 带宽敏感的长序列场景提供了可复制范式。

#### 3. PR #52628 — DeepSeek V4 ROCm 融合 AR draft 元数据更新
**技术解读**：#46849 恢复了多步 draft decode 的融合图，但 DeepSeek V4 的 ROCm 稀疏 SWA 因需要物化 ragged 索引而被排除。本 PR 让 AITER SparseSWA 元数据构建器在通用 dense SWA 更新后直接刷新持久化缓冲区（避免临时分配导致 HIPGraph 捕获的存储地址失效）。
**验证**：TP4 MI355X 上确认走融合 speculator 图路径，GSM8K/c16/c128 无 graph 回放错误或非法内存访问。
**影响**：这是"图模式 + 稀疏注意力 + 投机解码"三者兼容性的关键拼图，直接关联 #52644 反映的同类精度问题。

#### 4. PR #52648（已合并）— MXFP8 FlashInfer 路径可用性守卫
**技术解读**：FlashInfer CUTLASS MXFP8 kernel 的 `is_supported` 仅检查 `sm_100` 能力，未检查 FlashInfer 是否可导入，导致未安装 FlashInfer 的 Blackwell 环境在 `Marlin`/`B12x` 之前选中它并在首次 forward 崩溃。修复后补上 `has_flashinfer_cutedsl()` 式检查，并在 `mxfp8_utils.py` 的激活量化路径同样加守卫。
**影响**：这是一个典型的"依赖可选但选择路径不感知"缺陷，修复让 MXFP8 内核选择具备弹性降级能力。

#### 5. PR #48998（已合并）— Triton W4A16 qzeros 转置判定修复
**技术解读**：#47770 引入基于形状的 qzeros 转置判定，但两个候选形状相同时产生歧义。本 PR 改为优先使用元数据（`output_dim`），未设置时回退形状法，形状相同时默认 `transpose=True`。
**验证场景**：`cyankiwi/MiniMax-M3-AWQ-INT4` TP=8（此前失败）与 `Qwen3.6-27B-GPTQ-Int4` 均正常。
**影响**：对 GPTQ/AutoGPTQ 权重加载的"玄学"问题提供了确定性的修复方案，尤其保护了高 TP 并行下的 AWQ 场景。
