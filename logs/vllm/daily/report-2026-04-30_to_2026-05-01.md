    -   **核心议题**: Qwen2-VL 和 Qwen2.5-VL 模型在使用 `fp8_e5m2` KV Cache 且不计算缩放因子 (`calculate_kv_scales=False`）时，会静默产生错误的输出，尤其是在处理纯色图像时。
    -   **观点与立场**:
        -   报告者 `Ningke-Li`: 详细描述了 Bug 现象、分析了根因（Qwen 系列权重分布特性），并提供了两种可靠的解决方法。

    -   **争议焦点**: 主要在于**解决方案的激进程度**。是应该静默地自动切换 dtype，还是直接报错提示用户修改配置？社区倾向后者（fail-fast），认为更明确、更安全。
    -   **当前状态**: 讨论已达成共识，开发者 `maxiaosong1124` 将负责实施一个“快速失败”的配置校验。

### 🛠️ 重点技术变更

1.  **[ROCm] Native W4A16 GPTQ kernel for AMD RDNA3 (PR #41394)**
    -   **技术解读**: 本周期最重要的技术贡献之一。它通过编写原生 HIP kernel，绕过了 Triton 在 RDNA3 上的性能瓶颈，并解决了 `bf16` 模型精度问题。该 PR 实现了一个自适应调度：小批量（M<16）使用标量点积 kernel；大批量（M≥16）使用基于 `v_wmma` 的矩阵乘法 kernel。`gfx1101.cpp` 中的 `can_implement()` 函数用于优雅地回退，确保非 RDNA3 设备不受影响。这为 RDNA3 用户解锁了高性能且高精度的量化模型推理能力。

2.  **[ROCm] Feat: Support DeepseekV4-Pro on MI355 Platform (PR #41338)**
    -   **技术解读**: 将 DeepSeek-V4 这一先进模型引入 AMD MI355 平台是该阶段的重大进展。该 PR 并非简单移植，而是在 ROCm 平台上为 DeepSeek-V4 的独有技术（如稀疏 MLA、FP8 GEMM）实现了相应的回退和优化方案。例如，通过 `VLLM_DSV4_ROCM_WOA_BMM` 环境变量控制不稳定优化的开启，体现了谨慎的开发策略。这项工作的完成标志着 vLLM 在 AMD 旗舰硬件上支持最先进模型的决心。

3.  **[NVFP4] Add Triton kernels for NVFP4 dequantization and QDQ emulation (PR #40033)**
    -   **技术解读**: 由 AMD 员工 `fxmarty-amd` 贡献，但服务于包括 H100 在内的所有非原生支持 NVFP4 的 GPU。该 PR 使用 Triton 编写了融合的 NVFP4 反量化与 QDQ 模拟 kernel，替代了原始的 torch eager 实现。这带来的好处是双重的：一是显著的性能提升（在 MI300X 上 `vllm bench` 吞吐量提升 6.76-8.05 倍），二是解决了因大量小 kernel 堆积导致的 HSA/ROCm 驱动崩溃问题，提高了系统的稳定性。这是一个典型的“软硬件协同优化”案例。

4.  **[Attention][TurboQuant] Pad head_dim to power-of-2 for WHT (PR #41414)**
    -   **技术解读**: 修复了一个潜藏的、影响正确性的 Bug。TurboQuant 的旋转路径（Walsh-Hadamard Transform）假设 `head_dim` 是 2 的幂，但 Phi-2 等模型使用了 `head_dim=80`，导致矩阵乘法形状不匹配和运行时错误。该 PR 通过将 `head_dim` 填充到下一个 2 的幂，在 WHT 空间计算，再在输入输出边界截断，优雅地解决了问题。关键点在于该修复对2的幂 `head_dim` 模型是字节级等同的，确保了无回归。

5.  **[CI] Add MTP coverage: Qwen3.5 correctness + no-sync spec decode (PR #40472)**
    -   **技术解读**: 这是一个基础设施 PR，但影响深远。它增加了针对 Qwen3.5 模型 MTP 功能的端到端测试，以及无同步推测解码的测试。这确保了随着代码库快速演进，关键的 MTP 功能和推理正确性不会因其他修改而意外退化。对于任何支持推测解码的推理引擎来说，持续集成测试都是保证质量的核心。
