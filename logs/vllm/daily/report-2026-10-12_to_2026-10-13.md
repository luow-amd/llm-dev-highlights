#### 2. **#61126 — [Attention] Remove cascade attention**（8 条评论，作者 `WoosukKwon`）

**核心议题**：移除 cascade attention 的全部代码（kernel、启发式、metadata、scheduler 钩子、测试、文档），净减 901 行。

**立场与交锋**：
- **WoosukKwon（移除方）**：cascade 默认关闭、对 FlashInfer 硬禁用、多数后端不支持，却持续产生 per-step scheduler 扫描与分支开销；至少有 5 个 open issue（#55674/#47183/#39208/#55227/#53690）是在为它"打补丁"。
- **noooop（保留方）**：认为 JEV（`/v1/systemone`、`/v1/decisions`、clef-omni）正快速入驻 vLLM，这类场景**共享的 prompt 模板会产生大量同批共享前缀**，理论上 cascade attn 可加速 prefill。
- **反驳**：WoosukKwon 指出（1）prefill 是算力受限而非带宽受限，共享 HBM 读收益有限；（2）只有 FA4（本质上是 GQA 场景）真正支持 cascade；（3）根本不要混淆"移除 cascade"与"移除 prefix caching"。noooop 随后引用 FlashInfer PR #1015 的 multi-item scoring kernel 作为同类需求佐证，但未改变结论。

**最终结论**：已合并。`--disable-cascade-attn` 与 `disable_cascade_attn=` 保留为 deprecated no-op，计划 v0.33.0 彻底删除；插件侧 API 保留为 no-op 以不破坏 vllm-ascend/tpu-inference/vllm-gaudi/vllm-spyre/vllm-metal。

### 🛠️ 重点技术变更

#### 1. **#61126 移除 cascade attention**（净 -901 行 `vllm/`）

这是本次最影响架构简洁性的变更。Cascade attention 是早年为了在"同批多请求共享长前缀"场景下复用 KV HBM 读取而引入的，但从未成为默认路径。移除后：
- Scheduler 每步不再扫描 running request 的 block
- Model Runner 与各后端的分支被清理
- 5 个长期 open 的 cascade 相关 bug（含 #55674、#55227）自然消解

**风险评估**：对默认配置无行为变化；插件 API 保留为 no-op 避免破坏 vllm-ascend 等下游。但 JEV 场景的实际收益争议未完全解决，若未来出现共享前缀 decode 密集负载，可能需要以更通用的方式（如 FlashInfer multi-item scoring）重新实现。

---

#### 2. **#61316 → #61324 FP8 内核拒绝原因透传**

当前 `quantization="fp8_per_channel"` 在不支持 PTPC 的设备上会给出误导性错误 "Requires SM89+ for Cutlass FP8"，掩盖了真实原因（如 Marlin 不支持 per-token activation）。修复方案是让 `MarlinFP8ScaledMMLinearKernel.can_implement` 显式拒绝 W8A16 并附带 reason，从而让 `choose_scaled_mm_linear_kernel` 能完整抛出 `Reasons:` 列表。**这是一类典型的"错误信息即开发者体验"改进**，对在非 SM90+ 设备上调试 FP8 部署的用户价值很高。

---

#### 3. **#61171 [ROCm] 停止强制 HSA_ENABLE_IPC_MODE_LEGACY**（5 条评论）

背景：`HSA_ENABLE_IPC_MODE_LEGACY=1` 是当初为解决 UCX pin leak（#38503）而设置，但它使用的 ioctl 只在 DKMS 驱动实现；in-tree `amdgpu` 上 `hipIpcGetMemHandle` 会失败并破坏 RCCL P2P。

讨论后采取的折中方案（作者 `ChuanLi1101` 回应 `AndreasKaratzas` "CI 应保留该 flag"）：
- **CI base 阶段保留** `HSA_ENABLE_IPC_MODE_LEGACY=1`（CI 主机走 DKMS）
- **发布运行时镜像（final / vllm-openai）取消**
- 受影响主机可通过 `-e HSA_ENABLE_IPC_MODE_LEGACY=1` 显式 opt-in

值得一提：`xxraincandyxx` 独立做出了同一修复并主动撤回自己的 PR 支持此版；同时指出原 PR 未按 issue 要求补文档。这是一次良好的协作范式。

#### 4. **#61283 wheel 标签从 cp38-abi3 更正为 cp311-abi3**

`spinloop` 与 `fs_io_C` 使用了 3.10 / 3.11 才加入的 stable-ABI 符号（`PyObject_CallNoArgs`、`PyBuffer_Release`、`PyObject_GetBuffer`），`abi3audit` 在已发布的 v0.31.0 CPU wheel 上证实需要 3.11。虽然 `requires-python = ">=3.11"` 让安装侧无实际影响，但 wheel tag 与实际 ABI 需求不一致属于生态卫生问题，会误导打包工具链。
