### 🛠️ 重点技术变更

1.  **PR #48728 `[ROCm][Perf][DeepSeek V4] Fuse native FP8 shared expert into AITER MXFP4 MoE`**: **技术解读**：DeepSeek V4 的路由专家使用 MXFP4 量化，而共享专家使用 FP8。此 PR 通过在加载时将共享专家权重转换为 MXFP4，并将其作为第 384 个专家附加到 AITER 的 MXFP4 MoE 内核中进行计算。这避免了为共享专家单独启动一个 FP8 内核，通过复用高效的 MXFP4 内核路径来提升性能。它展示了 vLLM 在处理混合精度模型时的创新灵活性。
2.  **PR #48727 `[ROCm][Perf] Use AITER tgemm for DeepSeek V4 compressors`**: **技术解读**：DeepSeek V4 的压缩注意力（Compressed Attention）中的投影操作使用了 BF16 GEMM。本 PR 尝试用 AITER 库中经过高度调优的 `tgemm` 替换标准 `torch.mm`。 `tgemm` 是一个针对特定形状和架构进行了手工调优的 BF16 GEMM，能在保持精度的前提下（或进行权衡）显著提升矩阵乘法的计算速度。其中关于精度（BF16 vs FP32 累加）的讨论是决定该优化能否默认开启的关键。
3.  **PR #48712 `[Bugfix][ROCm] Only run FP8 AITER MLA prefill when using FP8 KV`**: **技术解读**：此 PR 修复了一个微妙的性能陷阱。即使不使用 FP8 KV Cache，ROCm 路径也会执行 FP8 预填充相关的元数据构建（`_build_fp8_prefill_ps_metadata`），该操作包含耗时的 Host-to-Device 同步。这就像一辆汽车，无论是否开启空调，都会启动压缩机能耗。修复后，只有当真正使用 FP8 格式时才会执行这一系列操作，符合“按需启用”原则，从而避免了不必要的性能开销。
4.  **PR #48746 `[CI][ROCm] Stabilize ci_base hash calculation and image handoff`**: **技术解读**：这是一个典型的 CI 基础设施优化。ROCm 的 CI 测试需要先从基础镜像构建一个 `ci_base` 镜像，然后基于它构建最终的测试镜像。问题在于，不同构建任务对同一个代码提交计算出的 `ci_base` 标签不一致，导致测试任务拉取不存在的镜像而失败。此 PR 通过多次计算并校验哈希值，以及显式传递 `ci_base` 镜像引用，确保了构建过程的确定性和 CI 的稳定性。
5.  **PR #48688 `[ROCm][Bugfix] Enable the fp32 head_dtype torch.mm fast path on ROCm`**: **技术解读**：此 PR 修复了一个“CUDA 偏心”的优化。vLLM 的 logits 处理器中有一个优化的快速路径，可以利用 `torch.mm` 的 `out_dtype=torch.float32` 参数，在数据类型为 bf16/fp16 时直接将结果累加为 fp32，避免了在 HBM 中物化一个巨大的 fp32 权重矩阵。然而，这个路径被错误地限制在了 CUDA (`current_platform.is_cuda()`) 上。`wjabbour` 验证了 ROCm 上的 `hipblasGemmEx` 同样能正确处理此组合，从而将这一关键优化扩展到 AMD GPU，大幅降低了 `lm_head` 计算的显存带宽消耗。

2.  **`#48752` GLM-5.2-FP8 + DSpark 在 Blackwell 上的 RPC 超时问题**：这个 Bug 规模大（涉及跨节点、大模型、投机解码），影响面广（多位不同硬件环境的用户报告），但目前讨论热度不高。如果与您的工作相关，强烈建议关注此 Issue，其修复方案可能会影响大规模的投机解码部署实践。
3.  **`#48393` 替代方案 `#48804`**：Eagle 投机解码的 Triton 内核预热。原 PR `#48393` 因依赖其他未合并 PR 而受阻。新的 PR `#48804` 采取了更独立、更彻底的方案，并覆盖了更多的内核类型。对于使用 Eagle 投机解码的用户，应关注此 PR 的进展，它有望解决首 Token 延迟中的 JIT 编译抖动问题。
4.  **`#48720` TP-wide 步进共识守卫**：这是一个非常深度的 RFC，旨在解决大规模 TP 场景下的死锁问题。它结合了 NCCL RAS、超时机制等先进方法。虽然目前看起来没有立即的行动，但它反映了社区在解决大规模分布式推理稳定性方面的深度思考和长期规划。
