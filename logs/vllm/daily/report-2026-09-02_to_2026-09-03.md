### 💬 高热度讨论分析

以下基于可获取记录挑选讨论深度最高的事件。

#### 1. Issue #54881（已关闭）：Gemma 4 启用 json_schema 后丢失 reasoning 并重复输出

- **核心议题**：同一模型、同一 prompt，在 0.23.1 上能正常生成 reasoning；升级到 0.26.1 后，`response_format.type=json_schema` 会导致 reasoning 为空、JSON 内容重复到 token 上限。
- **观点分歧**：
  - `AlejandroParedesLT` 最初认为这不是回归——Gemma 4 的 reasoning 默认关闭，#52430 修正了 parser 对默认值的处理，建议显式传 `enable_thinking=True`。
  - 报告者 `realmorita` 反驳：已经在请求中显式传入 `enable_thinking=true`；在 unmodified official image 上 0.26.1 仍可稳定复现。
  - `mukeshbhandarkar` 进一步分析：指 #52430 本身不解释该行为，真正嫌疑是 #52830 的 shared parser engine 重构——reasoning parser 与 tool parser 使用同一引擎时可能被折叠成 bare parser，导致 structured-output 侧重建 parser 时丢失 request 级 reasoning kwargs。
- **后续**：`realmorita` 在包含 #52830 的 `0.28.1rc1.dev278` 上复测，问题消失，主动关闭 Issue。
- **讨论价值**：这是典型的两个 PR 叠加导致的新行为回归，展示了多版本 bisect + parser 生命周期分析的方法。

#### 2. Issue #54907 + PR #54908：GLM-5.3 DCP 下 dense prefill 消费未初始化 K rows

- **核心议题**：TP4/DCP4 的 GLM-5.3 输出确定性 incoherent，而 DCP1 正常。`foraxe` 给出完整的根因：fused norm/rope kernel 在 `slot_mapping` 为负时直接返回，但 DCP 场景下负本地 slot 不代表该行无用，而是 cache row 属于其他 rank，导致非 owner rank 的 `kv_c_out`/`k_pe_out` 未初始化。
- **关键观点**：修复策略是将 **K 输出物化**与 **cache 写入**解耦——每个 rank 都必须物化请求的 K 输出，但只在 owner-local slot 上执行 cache 写入。
- **协作过程**：`ehfd` 在 Issue 中表示已部署到生产镜像并提供 patch 脚本验证；后又在 PR 中确认"GLM-5.3 问题在应用该修复后已解决"。PR 以 4×GB200、chunked prefill、prefix caching、FP8 KV、CUDA graph 的矩阵验证了 DCP4 与 DCP1 输出 SHA256 一致。
- **当前状态**：PR #54908 已触发 CI，等待维护者 review。

#### 3. Issue #54924 / PR #54925：GLM-5.3 在 ROCm 上被 MRV1 切换导致精度崩塌

- **背景**：#53155 为了使 GLM-5.2 维持 MRV1，将 `GlmMoeDsaForCausalLM` 放入 MRV1 carve-out；但由于 GLM-5.2/5.3 共享同一架构字符串，GLM-5.3 也被切到 MRV1，GSM8K 5-shot 从 91.6% 跌至 14.9%。
- **不同立场**：
  - `jimmy-adams`（报告者/修复者）：MRV1 对 GLM-5.3 产生 corrupted generations，应默认保留 MRV2；如果 GLM-5.2 确实需要 MRV1，应该用比 architecture string 更细粒度的判别方式。
  - `Rohan138`：MRV1 是有意为之——稀疏 MLA 在 MRV2 上因默认开启 async copy/streams 有约 20% 性能 regression；`mawong-amd` 已有 ROCm patch 落地，待 ROCm 10.1 后可重新审视默认值。此外 GLM MXFP4 在 MRV2 上的精度问题根因可能已由 #51915 修复。
- **争议焦点**：同一架构字符串下无法区分 GLM-5.2/5.3；性能（MRV1）与正确性（MRV2）的取舍需要维护者权衡。
- **当前状态**：PR #54925 open，等待 maintainer 决策。

#### 4. PR #54917：Gemma 4 E2B/E4B KV-shared 层权重加载结构修复

- **核心议题**：transformers 对 KV-shared 层不创建 `k_proj/v_proj/k_norm/v_norm`，而 vLLM 无条件创建，导致经 `save_pretrained` 的微调 checkpoint 出现 `uninitialized weights` 错误。
- **不同观点**：
  - 作者 `Josephasafg`：vLLM 应按 transformers 的条件逻辑创建模块；该 PR 取代已 stale 的 #41504。
  - Reviewer `aoshen02` 做了很深的技术分析：真正的根因是 **topology mismatch（模块拓扑不一致）**，不是 loader 能力缺口；早期 PR #41385/#44797 的"会破坏原始 Google checkpoint"的反对意见已因上游 checkpoint 行为变化而过时。此外要同时处理 redundant K/V names 的 skip 逻辑。
- **当前状态**：作者已按 Review 建议改为 conditional layer creation，CI 已触发，PR 仍在飞行中。

#### 5. PR #54955：DeepSeek-V4 batch-invariant kernels 中 top-k tie-break 语义不一致

- **核心议题**：该 PR 目标是让 vLLM rollout 执行与 batch 形状无关，从而用于 RL 训练的 0-diff actor 对齐。`bvolpato` 在 review 中发现一个潜在的前置正确性缺陷：`ds4_bi_topk_extension.cu` 的 local selection 使用"较大 local index 优先"，而 DCP merge 的 `StableTopKFromGatheredCandidatesKernel` 使用 `~token_id`、"较小 global ID 优先"。
- **技术意义**：在 all-equal scores 条件下，分片 selector 保留每个 shard 的尾部 token，而 unsharded selector 倾向保留不同于 shard 交叠的集合——两者在同一输入上可能选出**不同的 token 集**，破坏"batch-invariant / 0-diff RL"的前提。
- **当前状态**：PR 标注 **DO NOT MERGE** 的 preview，作者计划在验证后拆分多个 PR（kernel、sparse attention、MoE/DeepEP、reload 支持）再合入。tie-break 对齐问题需要纳入拆分前的修正。

### 🔥 热门话题与趋势分析

#### 1. GLM-5.x / DeepSeek 新一代混合架构成为正确性修复主战场

本窗口中大量 Issue/PR 围绕 `GlmMoeDsaForCausalLM`、DeepSeek-V3.2/V4、MLA/DSA/稀疏索引、KpoolTail 等混合注意力 + MoE 结构展开。#54907 的 DCP K-materialization、#54924 的 MRV 切换、#55053 的 MTP/MoRI-IO 块偏移、#55035 的 KpoolTail 调度，均属于"新架构在大规模并行/offload 组合下暴露的边界语义"问题。

#### 2. MRV1 → MRV2 过渡期的默认行为争议

`ROCM_DEFAULT_MRV1_ARCHITECTURES` 这类架构到 runner 的映射策略正在引发连锁问题。新模型（GLM-5.3、DeepSeek-V4 变体）与旧模型共享架构字符串，无法用简单列表表达"某版本需要 MRV1、另一版本需要 MRV2"的细粒度策略。

#### 3. 工具调用与结构化输出 parser 线上可靠性

新增了多个 tool-parser bug：#54971（GLM-4.7 参数 tag 泄漏进 key）、#55080（`tool_choice='none'` 时删除工具形态内容）、#55082（step3 流式参数为空）、#54881（Gemma 4 结构化输出与 reasoning 交互）。这说明 vLLM 的 parser 层仍是生产环境的主要摩擦点。

#### 4. AI agent/自动化辅助代码生成对开发流程的影响

大量 PR body 中出现 "Made with Cursor"、"Generated with Claude Code"、"AI assistance used" 等声明；同时 `fxmarty-amd` 在多个 Issue 开头加入了 "automated unfinished PRs will likely not get reviewed... do not open PRs autonomously" 的警示。本窗口还观察到多个 PR 因 branch base 历史错误、重复提交而由作者主动关闭（#55034/#55035/#55064/#55060/#55007）。社区正在尝试吸收 AI 贡献收益的同时抑制噪声。

#### 5. Speculative decoding / MTP 的正确性验证

#54928（DFlash2 在 token 30 处与 greedy 不等价）、#55081（14 个 MTP drafter 的 SupportsPP mixin）、#54908（DCP 与 spec decode 组合）表明：投机解码已从
