- **核心议题**：GDN decode 是 memory-bound，每步都要读写 recurrent state；ReplaySSM 用 ring buffer + 周期性 checkpoint 替代每步全量 state 写回。

### 🛠️ 重点技术变更

#### ① #68839 — Hy4 / Hy4-Flash ROCm 启用（**本周最具战略意义**）
- **技术要点**：把模型代码拆为 `common/`（vendor-neutral）与 `nvidia/`、`amd/`（vendor-specific），`__init__.py` 按平台 dispatch。ROCm 路径依赖 AITER 的 Triton sparse MLA（`VLLM_ROCM_USE_AITER_TRITON_SPARSE_MLA=1`），直到 ROCm/aiter#6277 合入并 bump。
- **影响**：这是 **per-vendor 模型布局的第二个落地案例**（前有 `muse_spark`），确立了 vLLM 多硬件模型支持的目录范式；同时证明中国厂商模型（腾讯 Hy4）在 AMD 顶配卡上的可用性达到 MMMU-Pro 反超官方报告的水平。

#### ② #62004 — ReplaySSM for GDN（**算法级创新**）
- **技术要点**：用 ring buffer 缓存 `k`（key）、`d`（corrected value）、`g`（scalar gate），配合周期性 checkpoint state，把每步的 recurrent state 全量写回（`head_v × head_k` 矩阵）替换为小 input append；每 L 步才 flush 一次。baseline 在 large batch 才 bandwidth-bound（H100 bs=1 仅 9.0% peak），因此收益随 batch 增大。
- **影响**：这是 **Hybrid SSM 推理的第一个系统性 memory-traffic 优化**，且已证明可跨 CUDA/ROCm 移植。与 #69699 的 prefix-cache 标准化结合，可能成为 GDN 推理的默认路径。

#### ③ #67306 — Muse Spark Decode MoE 原生路由
- **技术要点**：AITER 路径会把每个 token 的 row 重复 `top_k` 次再喂给 experts；新路径用 `[T, top_k]` 原生 routes（T 行而非 T×top_k 行），router split-K reduce + top-k + pre-expert RMSNorm 融合为单 Triton kernel，stage-1 MXFP4 quant 与 sort 也融合为单 launch（≤512 tokens）。
- **影响**：MI355X TEP4 上 D=8/16/24/47 全部提速 4-5%，且 **CPU launch overhead 显著下降**，是 "AMD 上小 batch decode" 的范式改进。

#### ④ #69098 — 媒体预处理内存硬上限（**安全关键**）
- **技术要点**：`VLLM_MAX_MEDIA_PREPROCESSING_BYTES` 独立于请求下载/解码预算；处理器在**物化之前**估算 tile/audio padding/video pixel tensor，超预算返回 HTTP 400。FunAudioChat 还需要区分 raw audio（受 byte cap）与预计算 `audio_embeds`（保留 item limit）。
- **影响**：关闭了多个 DoS advisory；同时暴露了"MM limits 语义混杂"的设计债——同一个 `get_supported_mm_limits()` 既表达 item 数又表达字节预算，后续可能需拆分接口。

#### ⑤ #69699 — Mamba Prefix-Caching 迁移审计（**架构级 tracking**）
- 若落地，将把 Mamba 家族（Mamba1/2、GDN、KDA、ShortConv）的 prefix-cache 从两条路径收敛为单一路径 `MambaPrefillCheckpointBuilder/Exporter`，消除 split-prefill 在 fine prefix-match 下 30ms 的 TTFT 惩罚。已有 `vyomakesh0728`（Mamba1）、`Ra5hidIslam`（GDN cutedsl）认领。
