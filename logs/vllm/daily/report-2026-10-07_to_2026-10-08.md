### 💬 高热度讨论分析

#### 1. #57560 [ROCm][Perf] Add AITER FlyDSL GDN prefill backend
- **核心议题**：为 ROCm 增加 AITER FlyDSL GDN prefill 后端，是否具备合入条件。
- **观点与立场**：
  - `simondanielsson` 要求补充 e2e GPU 正确性测试、GSM8K before/after，并询问是否需长上下文（256k ISL）A/B。
  - `mjkvaak-amd` 补充 e2e 测试、GSM8K 结果（0.9787 vs 0.9825，认为在噪声内），并解释 GPQA 差距仅 3/198 题，属运行方差。
  - 关于默认后端，作者说明 ROCm 上 `auto` 仍解析为 Triton，只有显式请求才走 `aiter_flydsl`，因此长上下文回归风险可控。
- **争议焦点**：性能收益是否足够稳定、是否需要更大规模长上下文验证。
- **结果**：已合并，作为 opt-in 后端进入。

#### 2. #55053 [Bugfix][KV Connector][ROCm] Fix MoRI-IO KV block-offset for speculative decoding (MTP)
- **核心议题**：MoRI-IO + MTP 下 prefill 侧多出 speculative lookahead block，导致 `local_block_ids longer than remote_block_ids` 崩溃。
- **观点与立场**：
  - `tjtanaa` 要求提供端到端 GSM8K、并发 128、草稿接受率。
  - `simondanielsson` 多轮审查，要求裁剪逻辑考虑任意 block size、用 `num_prompt_tokens` 而非 `num_speculative_tokens`、修复 chunked-prefill 最终块检测、对 SWA+MTP 采取 fail-fast。
  - `MohitAMD` 逐项响应：将裁剪限制在 WRITE producer 保存路径，READ 仍保留 loud raise；按 prompt token 进度检测最终 prefill chunk；对 SWA+spec 抛 `NotImplementedError`。
- **争议焦点**：surplus 应丢弃还是断言、裁剪位置、是否支持 SWA+MTP。
- **结果**：已合并，并加入多组回归测试。

#### 3. #56638 [ROCm][DSv4.1][Perf] Replace the Torch prefill combine with shared kernel
- **核心议题**：用共享 `combine_topk_swa_indices` kernel 替换 ROCm Torch prefill combine，是否合入。
- **观点与立场**：
  - `ChuanLi1101` 质疑性能收益不明确、TTFT 仅单次运行、范围超出 gfx950、测试参考不独立、`num_tokens` clamp 改变语义。
  - `JohnQinAMD` 回应：修复 prefill-only 影响，补充 `torch.equal` 测试覆盖 `seq_len < query_len`、`seq_len == 0`、`compress_ratio == 0`、非 128 window，并保留 Torch 路径作为 oracle。
- **争议焦点**：性能证据强度、跨架构覆盖、clamp 语义与测试独立性。
- **结果**：已合并。

#### 4. #60397 [ROCm][Perf][DSv4.1] Mono decode layer for DeepSeek-V4.1-Flash on MI355X
- **核心议题**：大规模 kernel 融合的 mono decode 路径是否足够正确，能否合入。
- **观点与立场**：
  - `benchislett` 认为仅 GSM8k 不足以验证，要求至少 GPQA-D 和 AIME25，防止数值泄漏。
  - `tjtanaa` 进一步要求长上下文 NIAH 评估。
  - `Fangzhou-Ai` 运行评估后发现真实 bug 并修复，补充 GPQA-D、AIME25、NIAH，并新增 `test_dsv41_mono_numerics.py` 分阶段数值测试。
- **争议焦点**：大范围 kernel 融合的正确性验证标准。
- **状态**：仍 Open，审查中。

#### 5. #41485 Qwen3-VL deepstack ValueError 回归（窗口内关闭）
- **核心议题**：v0.20.0/v0.20.1 中 Qwen3-VL deepstack 在 chunked prefill + prefix caching 下 engine 崩溃。
- **观点与立场**：
  - 多名用户确认 `v0.20.0` 和 `v0.20.1` 均受影响。
  - `cjackal` 指出已知回归来自 #40932，呼吁在 v0.20.1 前 cherry-pick，并称“大多数 v0.20.0 用户一小时就会遇到”。
  - 有用户发现关闭 chunked prefill 和 prefix caching 可规避。
- **结果**：因 stale 自动关闭，但暴露了版本发布 cherry-pick 流程问题。

### 🛠️ 重点技术变更

1. **#57560 AITER FlyDSL GDN prefill backend（已合并）**  
   为 ROCm 增加 GDN 预填充优化后端，支持 BF16、128 维头、GQA ratio 2。虽然默认仍为 Triton，但为后续 MI355X 上 Qwen/GDN 类模型预填充性能提升铺路。

2. **#59685 AITER MegaMoEV2 集成（已合并）**  
   将 DeepSeek-V4 的 routed experts 融合为 4 个 kernel（prepare、stage1、stage2、combine），替代原先约 10 个 kernel，代表 AMD 在 MoE 融合方向的重要进展。限制条件为 gfx950 + DP/EP + MoRI + 无 EPLB。

3. **#55053 MoRI-IO KV block-offset 修复（已合并）**  
   解决 PD 分离 + MTP 下 prefill 侧 lookahead block 导致 decode 崩溃的问题，是 MoRI-IO 在生产级投机解码场景可用的关键修复。

4. **#60397 DSv4.1 Mono decode layer（Open）**  
   在 MI355X 上为 DeepSeek-V4.1-Flash decode 引入 persistent FlyDSL 启动，将每层约 40 个 kernel 替换为 K1/K2，并融合 TP all-reduce。若合入，将显著降低 decode 启动开销，但需通过 GPQA-D、AIME25、NIAH 等严格数值验证。

5. **#46963 NVFP4 KV cache on SM8x and SM12x（已合并）**  
   扩展 `--kv-cache-dtype nvfp4` 到 SM8x/SM12x，通过 FlashInfer 实现 paged KV 写入与 fa2 读取，SM80 上 KV cache 容量提升 3.32×，对非 Blackwell 平台量化推理意义较大。

6. **#60517 移除 torch.compile-based sequence parallelism 与 AsyncTP（Open）**  
   由 WoosukKwon 发起，可能简化编译栈、减少维护负担，但会影响依赖该特性的用户与并行策略，值得关注后续讨论。

### 💡 值得关注的问题

1. **MoRIIO 连接器生产可用性**  
   #60474、#60473、#60425 分别暴露 TP 不匹配崩溃、notify 端口静默失败、KV cache 未释放。这些问题会在一线 PD 分离部署中导致 decode 逐台失效、请求挂起或 GPU 无法重启，建议优先修复。

2. **ROCm 上 GLM-5.2-FP8 前缀缓存静默错误**  
   #60494 在 prefix cache 命中后返回空 content 与乱码 reasoning，且无 traceback，属于高风险静默失败，需 ROCm 团队尽快定位。

3. **NIXL BLHNC MLA 注册退化**  
   #60561 指出 #53781 的 `not page_contiguous` 门控使 BLHNC MLA cache 失去 whole-row 注册，描述符数量反而高于 LBHNC，性能退化明显，已有 #60564 提出 opt-in 修复。

4. **调度公平性回归**  
   #60476 `--long-prefill-token-threshold` 因 #57951 的 lone-request exemption 失效，短请求被长 prefill 阻塞，#60485 提出在豁免超阈值后不调度新 batch 的修复思路。

5. **AOT 编译 artifact 按 rank 分裂**  
   #60391 指出多 rank 下部分 rank 加载失败会独自重编译，可能导致 collective 不匹配；#60463 采用两次 `all_gather_object` 使决策 collective 化。

6. **EPLB async rearrangement 崩溃**  
   #60455 中 GLM-5.3-Flash 在 EPLB 异步重排时 OOM 并触发 SharedExperts AssertionError，需区分异步重排失败与后续 OOM 的因果关系。

7. **DeepGEMM JIT 服务停顿**  
   #60536 报告 GLM-5.3-Flash 在 prefill 阶段 JIT 编译 20 个 `sm100_tf32_hc_prenorm_gemm` split-K 变体，导致 2.5–14 秒不等的 TTFT 尖刺，启动 warmup 覆盖不足。

8. **新模型入树政策争议**  
   #60431 TR-HASH 被 DarkLight1337 以“模型不够流行”为由拒绝入树，建议走插件机制。该决策可能影响社区贡献者对 vLLM 模型支持范围的预期。

9. **移除 torch.compile sequence parallelism/AsyncTP**  
   #60517 若合入，将改变部分并行训练/推理场景的编译行为，需关注对现有用户的影响及迁移建议。
