### 🛠️ 重点技术变更

1.  **PR #44308: [ROCm] Fix AITER RMSNormQuantFusion for Kimi-Linear**: 该 PR虽小，但技术意义重大。它展示了 AMD 团队在将新模型（Kimi-Linear）无缝集成到其优化的 AITER 运行时中所做的努力。修复了 `KimiGatedDeltaNetAttention` 使用 `num_heads` 而非 `num_v_heads` 的属性差异，体现了对特定模型架构的深入理解。此 PR 已快速合并。

2.  **PR #44282: [Bugfix] Vendor MiniCPMV/MiniCPMO processors to unblock Transformers v5**: 此 PR 解决了 Transformers 库版本升级带来的兼容性问题。通过将这两个多模态模型的处理器代码内联（vendor）到 vLLM 项目中，确保了即使上游 Transformers 发生重大变更，vLLM 仍能稳定运行这些模型，体现了 vLLM 项目维护的务实策略。

3.  **PR #42187: [ModelRunnerV2] Avoid pipeline parallel bubbles**: 这是一个结构性的性能优化 PR，重构了 Pipeline Parallelism（PP）下的调度和通信方式。通过在 decode 阶段合理安排不同 PP 阶段的 token 计算，以及使用独立的 stream 和 process group 来广播采样后的 token，显著减少了 PP 流水线中的空泡（bubble），从而量化地提升了吞吐量（最高可达 3.17x）并降低了 TTFT（最高 3.15x）。

4.  **PR #43339: [Feature] Support EPLB for DeepSeek v4 Mega Moe**: 该 PR 为 DeepSeek V4 的 MoE 架构添加了 Expert Parallelism Load Balancing (EPLB) 支持。EPLB 旨在解决大规模专家并行中可能出现的负载不均问题，通过智能的负载均衡策略，优化 GPU 集群的利用率，对部署 DeepSeek-V4 这类超大模型至关重要。

5.  **Issue #44300: [Feature]: Could you help with implement the KV cache pruning feature on vLLM?**: 虽然还未有合并的 PR，但此功能请求展示了 KV Cache 优化领域的巨大潜力。提出者 `sankexin` 展示了在 DCU 上集成多种 KV 缓存剪枝算法后，在 RULER 基准测试中几乎无损的准确率，以及高达 55% 的生成速度提升。如果该功能正式引入 vLLM，将有望显著降低推理成本和提高长序列处理能力。

### 💡 值得关注的问题

1.  **KV Cache Offloading 性能降级 (#44294)**: “OffloadingConnector” 在并发请求共享前缀时，因序列化加载导致 TTFT 膨胀高达 12 倍。这直接影响了 CPU/GPU 异构部署和分离式推理场景下的用户体验，是一个需要紧急关注的性能回归。
2.  **FlashInfer 采样器与 Blackwell GPU 兼容性 (#44305)**: 在最新的 NVIDIA Blackwell GPU 上，FlashInfer 采样器因 CUDA 工具链版本不一致导致 JIT 编译失败。虽然用户可以设置环境变量绕过，但这是新硬件平台的一个初始障碍，需要 FlashInfer 团队协同解决。
3.  **Logprobs 值依赖于请求数量 (#44319)**: 用户报告了一个令人困惑的行为：当请求不同数量的 logprobs 时，返回的 logprob 值不同，这影响了模型预测的可信度。这可能是一个潜在的内部归一化或采样策略 Bug，需要 vLLM 核心团队深入排查。
4.  **Rust 前端与 Python 前端的行为一致性**: 随着 Rust 前端功能的不断丰富，确保其在与 Python 前端相同场景下的行为完全一致（如请求 ID 头的处理、API 密钥认证逻辑、Chat Template渲染等）将是重要的测试和质量保障点。
