### 🛠️ 重点技术变更

#### 1. #51011：fp8 KV cache 静默错误的根因剖析

该 PR 是**正确性修复的教科书案例**。Kimi-K3 TP8 下 12 heads/rank 触发三个独立 bug：
- fp8-only 的 Gluon regime 断言 `batch_size==1`，多请求并发直接 crash；
- 推测解码 qlen 元数据方法名硬编码，表索引 KeyError；
- 最危险的是 ***padded head count 后 `use_persistent_metadata` gate 错误*，导致输出静默错误**——GSM8K 仅 74%，且无任何报错。

修复后 fp8 达到 97.65%，反超 bf16 的 97.19%。**影响**：为 ROCm 上 fp8 KV cache 的可用性扫清了最大障碍，同时为"head padding 必须同步调整 metadata 路由"提供了工程教训。

#### 2. #51718：KV-Cache Layout Refactor 6/N

- 所有 KV cache 统一为逻辑 `[L, B, H, N, C]` 词汇表；
- `KVCacheLayout` 枚举 6 种物理排列（LBHNC/LBNHC/LHBNC/BLHNC/BLNHC/BHLNC）；
- 布局单一决策源发布到 `CacheConfig`：test override > backend-required > env > connector preference > 默认 LBNHC；
- 移除 `indexes_kv_by_block_stride` 等 per-backend hooks。

**影响**：这是 kv-connector 生态（NIXL/Mooncake/MoRI/HF3FS/offloading）和 attention backend 的共同底层契约。`#51722`（AITER 独立 head groups）正是该系列中 ROCm 侧的配套变化。

#### 3. #51695 + #51754：FSE 跨平台落地

- **#51695（AMD）**：建立 `resolver` 统一校验 FSE 与 quantization config 的兼容性；模型间行为一致性（全部层 FSE 或全部不 FSE）；不兼容时不再静默 fallback，而是明确报错。为后续通过任意量化方法启用 FSE 铺路。
- **#51754（NVIDIA）**：FusedMoE 中将 shared experts 表示为 always-on routed slots；合成 shared route 与 top-k 打包在单个 Triton kernel 中完成，避免单 token decode 路径的性能回退；保护 ROCm AITER 原生路径。

**影响**：FSE 从"ROCm/AITER 独占特性"变成"跨平台共同抽象"，同时保持各平台 kernel 实现差异化。

#### 4. #51647：AITER MLA head padding

对非 16 对齐的 query heads 做 padding 到 16 倍数，输出再 slice 掉。让 Kimi-K3 TP4 的 24 heads/rank 使用 AITER MLA 而非回退 Triton。MI355X 实测数据：

| 指标 | Triton MLA | AITER padded | 变化 |
|---|---|---|---|
| TPOT（C16） | 62.7ms | 41.0ms | **-34.6%** |
| 吞吐（C24） | 256 tok/s | 374 tok/s | **+45.9%** |

**影响**：直接决定了一批模型（head count 非 16 倍数）能否吃到 AITER 性能红利，对 TP sharding 下的 head 分配策略也有参考价值。

#### 5. #51507：采样器 warp 优化

`num_warps=4→8` 的 launch 配置改动，带来 1.2~1.85x 的 kernel 级加速，e2e 采样从 305.8µs 降到 165.9µs。该 kernel 是 seeded/per-request-generator sampling 的独占路径（FlashInfer 不适用），对兼容性场景影响直接。H200/MI350X/SM120 三平台交叉验证后合入。
