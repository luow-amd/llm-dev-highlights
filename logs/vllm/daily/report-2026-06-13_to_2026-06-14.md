### 🛠️ 重点技术变更

1. **PR #45546 — MiniMax-M3 AMD EAGLE3 支持**：**最具平台意义的合并**。通过给 AMD 侧模型类添加 `SupportsEagle3` mixin，使推测解码在 MI355X 上可用。本质上是平台分叉模型的一致性维护。

2. **PR #45559 — ROCm GFX12 SWMMAC 瘦 GEMM**：**AMD 性能优化**。利用 RDNA4 的稀疏波矩阵乘指令优化小 batch 下的 GEMM 性能。该方向与 Hugging Face 博客和 IREE 项目的优化思路一致，表明 vLLM 在 AMD 架构上的 Kernel 优化进入精细化阶段。

3. **Issue #45562 — MI300X FP8 KV cache 精度崩溃**：**当前最重大 Bug**。根因是 AMD EPYC 平台使用的 `float8_e4m3fnuz` 与 NVIDIA 的 `float8_e4m3fn` 编码不兼容，而 MiniMax-M3 的 sparse attention 后端硬编码了后者。此问题可能导致所有在 AMD 上使用 FP8 KV cache 的模型输出完全错误，亟需修复。

4. **PR #45460 — Tokenizer pickle 修复**：**影响广泛的 Bug 修复**。`maybe_make_thread_pool` 函数因缺少 `return` 语句导致封装后的 tokenizer 反序列化为 `None`，破坏了跨 Ray/多进程的 tokenizer 传递。合入后恢复高可用部署的关键链路。

5. **PR #45554 — cumem 跨 rank 静默屏障**：**sleep mode 关键修复**。解决 TP+PP 部署下 `cuMemUnmap` 操作与 NCCL 广播之间的竞争条件，通过在 VMM 突变前后加入全局同步，避免了 `cudaErrorIllegalAddress` 崩溃。这是 sleep mode 在多卡场景下能可靠工作的基础。

### 💡 值得关注的问题

1. **MI300X FP8 KV cache 精度失真的根因修复** — Issue #45562 尚未有关联 PR，而它可能使所有 AMD 上使用 FP8 KV cache 的模型产生错误输出。该问题具有高影响、高紧急度，建议社区尽快介入。

2. **Tied word embeddings + ModelOpt 量化加载崩溃** — Issue #45543 暴露了 #39612 重构后，`tie_weights` 委托到量化方法时 `NotImplementedError` 未被正确覆盖。影响 Gemma 等模型。虽然 PR #45544 提出了修复，但尚未合并。

3. **V1 Scheduler 优先级抢占与 `max_num_seqs` 矛盾** — PR #45558 和 #45561 都针对 Issue #40004 提出解决方案，但两份 PR 的实现和角度不同（一个在 kernel 层做预取，一个在 scheduler 层做抢占），可能产生重复或冲突，需要维护者协调。

4. **`/sleep` 与 `/wake_up` 仍需 drain 语义** — Issue #45520 揭示当前 `/sleep` 在有飞行请求时返回 200 但引擎崩溃的“撒谎”行为。虽然 #45552 修复了同步问题，但更根本的 drain 机制尚未实现，高可用 swap 场景仍需谨慎使用。
