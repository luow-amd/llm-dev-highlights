### 💬 高热度讨论分析
按可见评论数（含机器人/CI 评论）及实质讨论密度，主要热点如下：

1. **#47630 [Bugfix][OpenAI] 在 beam search 中尊重 `allowed_token_ids`（5 条评论，已合并）**
   - 核心议题：OpenAI 兼容接口的 beam search 路径丢失 `allowed_token_ids`，可能 HTTP 200 返回被禁止 token。
   - 观点分歧：作者 `Sunt-ing` 提供真实 Qwen3-0.6B 复现，主张修复；维护者 `DarkLight1337` 担心 engine core 改动过大，认为功能 popularity 不足以支撑复杂改动。
   - 折中：作者提出 frontend-only 替代方案（+157/-12，上限 128 IDs，不与 structured outputs/speculative decoding/diffusion 组合），以降低侵入性。
   - 状态：已合并，说明最终接受了受限范围的修复。

2. **#62207 [Frontend] 新增 Muse Spark Open reasoning/tool parsers（5 条评论，Open）**
   - 核心议题：新 tool parser 的字符串参数被错误转成数字。
   - 具体观点：`ryansalatin` 报告 `--tool-call-parser muse` 下 schema 为 `"type": "string"` 的参数 `25` 被返回为数字 `25`；原因是 `_decode_value` 对每个参数值直接 `json.loads`，未查询工具 schema。
   - 影响：与 #62252 的 Qwen3 `["string","integer"]` 强制转换问题同属“schema-aware 解析缺失”，可能静默改变标识符、版本号、账号等字符串。
   - 状态：PR 仍 Open，已有 CI 触发，需作者修正解析逻辑。

3. **#62211 [KV Transfer] Connector-agnostic KV checksums for P/D disaggregation（4 条评论，Open）**
   - 核心议题：为 P/D 分离引入与 connector 无关的 KV checksum，生产端校验发送内容、消费端校验接收内容，不匹配按 KV load failure 处理。
   - 不同观点：`yubofredwang` 不反对当前范围，但担心未来扩展到持久化 KV 存储（Mooncake store、CPU offload、LMCache）时流程需重构；当前 checksum 走 worker→scheduler→`kv_transfer_params`，而存储型 connector 需要在 save 时按 chunk 写入对象 metadata，在 load 时提供 expected values。
   - 建议：增加 checksum worker 与 connector 之间的 block-level hook，保留 scheduler compare 用于 P/D，同时让 connector 在 save/load 时接管 per-block 值。
   - 状态：Open，且有 merge conflict；设计上需考虑未来持久化 KV 生态。

4. **#61045 [Bug] Gemma 4 encoder CUDA graph capture OOM（3 条评论，已关闭）**
   - 核心议题：开启 encoder CUDA graphs 后按 `max_frames_per_batch` 分配全图行，RTX 5090 32GB 上捕获时 OOM。
   - 观点：`ischencheng` 提出 #61092 将 capture rows 限制为 `token_budget // 70`；`michaelmanly` 复现并指出禁用 encoder CUDA graphs 只是配置规避，不是修复；报告者 `toan-tq` 确认这是视频路径验证而非生产负载，#61092 即视为修复。
   - 结论：关闭，后续由 #61092 解决行数预算问题。

5. **#61947 [Bugfix][Frontend] 保留 Cohere/Anthropic streaming errors（4 条评论，已合并）**
   - 核心议题：流式响应中 parser/generation 失败未被正确保留；审查建议暴露原始 chat chunks，由各 API 输出边界转换，避免中间 JSON 序列化/反解析。
   - 讨论以 review 反馈、CI 重试和作者 ping 为主，技术争议较小。
   - 状态：已合并，新增 raw stream generator 并覆盖 Cohere/Anthropic 错误路径。

### 🛠️ 重点技术变更
1. **#58761 ROCm 10.0 成为默认栈**
   - 这是 AMD 生态的基础设施级变更：默认镜像、wheel 索引、CI 构建全部切到 ROCm 10.0，ROCm 7.2 以 `-rocm72` 过渡。
   - 影响：AMD 用户安装路径、CI 缓存键、镜像标签、wheel 依赖解析均变化；同时暴露 wheel 与镜像 patch 不一致、amdsmi 硬件验证等后续工作。

2. **#61278 AITER tuned configs 驱动 a4w4 GEMM 布局选择**
   - 从全局 env var 改为按层决策：仅当 AITER 同时具备 ASM 与 preshuffled Triton 调优配置时使用 preshuffled/ASM 布局。
   - 影响：Llama 类模型获得 TTFT/TPOT 改善，Kimi/DeepSeek 等无调优模型避免回退；减少用户手动调参负担，是 ROCm 性能工程化的重要一步。

3. **#62202 RDNA3 MXFP4 扩展到 gfx1151 与 DeepSeek-V4**
   - 将 gfx1100 的 MXFP4 内核开放到 gfx1151（Strix Halo/Radeon 8060S），并针对 gfx1151 的 WMMA-16 低效改用 scalar tile。
   - 影响：消费级/APU AMD GPU 获得原生 MXFP4 路径；DeepSeek-V4 的 MoE 专家可走 `RDNA3_MXFP4`，对边缘/工作站部署意义较大。依赖 #46676，属于 stacked PR。

4. **#58857 DeepSeek-V4/V4.1 VL 权重流式加载**
   - 原实现用 `sorted()` 物化整个权重流，导致 eager/fastsafetensors 加载时近整个 475 GiB checkpoint 同时驻留，引发 host OOM；新 helper `stream_language_model_first` 只保证 `language_model.*` 非交错，延迟 vision tower/aligner。
   - 影响：大幅降低大模型加载峰值内存，尤其对 DeepSeek-V4.1-Flash 这类超大 checkpoint；AMD V4.1 wrapper 的 #58782 也可复用该思路。

5. **#62027 Qwen3 工具参数流式解析线性化**
   - 原实现每个 delta 重新解析完整 JSON 参数，长参数呈二次复杂度；采用 `arg_value_extender` 后，12 KB `write_file` 调用解析时间 2.1 s→11 ms，25 KB 8.4 s→22 ms。
   - 影响：覆盖 qwen3_coder、qwen3_xml、Seed-OSS、Step3p5、Nemotron-v3、Granite thinking、MiniCPM-V 等 parser，直接改善 coding agent 长工具调用场景的 API server CPU 开销。

### 💡 值得关注的问题
- **#62252 工具参数 union schema 强制转换错误**：`["string","integer"]` 下 `"0017"` 被转为 `17`，影响 ZIP、账号、版本号等字符串语义；已有贡献者表示将修复并保留非规范数字文本。属于静默数据损坏类问题，优先级应较高。
- **#62225 CPU backend LoRA 混批污染**：base 请求与 LoRA 请求同批时，base 请求被应用 adapter，且无报错。已有 #62227 指向 `-1` “无 adapter”索引在 torch/CPU punica op 中回绕到最后一个 adapter slot。对 CPU 生产用户影响严重。
- **#62144 NixlConnector P/D TTL 驱逐后 libfabric `connect()` 阻塞 60 s**：远程 agent 被 TTL 驱逐后，pull、heartbeat、deferred notification 仍可能访问，导致 worker 线程串行阻塞、DP engine 饿死。属于生产级可靠性问题。
- **#62217 / #62216 / #62153 非 CUDA 路径回归**：HiSparse 双 async KV load 卡死 scheduler、LMCache `use_native` 缺少 `get_kv_events`、Mamba2 hybrid CPU 长 prompt 崩溃。建议补齐 CPU/Mamba/HiSparse 回归矩阵。
- **#62211 KV checksum 的持久化存储扩展设计**：当前 P/D 流程可用，但 Mooncake store、CPU offload、LMCache 等持久化 KV 需要 block-level hook 和对象 metadata 级 checksum，否则未来可能重构。
- **AMD 侧临时缓解与实机验证**：#62161 将 ROCm watchdog 提到 1800 s 只是为 AITER JIT 让路，根因需 AITER 预构建模块；#62241 尚未在 MI355 上稳定验证；#62202 依赖 #46676。AMD CI 的长期稳定性仍依赖上游 AITER/ROCm 修复。
- **#62187 文档技术债**：Out-of-tree quantization 文档仍使用已移除的 `FusedMoE` 和旧 `apply` API；社区指出 #50598 已覆盖但长期未推进，需 maintainer 推动 rebase/合并。
- **#62175 Q4 OPD Teacher Serving roadmap**：教师模型评分、prefix-cache 复用、AuxOutput score reuse、TP 下 candidate 集成等路线图值得跟踪；评论中已提出长上下文/大词表场景的 payload 与显存 sizing 估算需求。
