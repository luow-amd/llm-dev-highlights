### 🎯 AMD/ROCm 生态相关动态

**本周期 AMD 相关改动高度活跃，涵盖性能回退修复、新 Kernel 合并、CI 稳定性及显存优化。**

#### 1. 性能回退修复与 CUDA Graph 恢复
- **#48446**（已合并）：将 ROCm 上的 `all_gather` 回退到基类集合通信，避免 #40996 引入的每步额外开销（DeepSeek-V4 在 MI355X 上 TPOT 从 32.5ms 恢复至 26.4ms，提升约 22%）。

- **#48526**（新增 PR，待合并）：重新启用 ROCm 的 CUDA Graph 剖析，但改为在当前流上捕获以避免侧流导致的 scratch buffer 放置偏差，在 MI355X 上恢复吞吐至与禁用剖析相同水平（从 79.9 tok/s 恢复到 98.4 tok/s）。  

#### 2. 新 Kernel 与模型支持
- **#40977**（已合并，近期合并）：为 ROCm 引入混合 W4A16 线性 Kernel（Triton 预填 + HIP 瘦解码），在 gfx1151/gfx1201 上对 Qwen3-4B、Gemma 3-4B 等模型实现 3~4 倍 TPOT 加速。作者为 AMD 员工 `mgehre-amd`。  
- **#44849**（已合并）：为 MiniMax-M2 的 QK-norm 融合 AITER 的 `custom_fused_qknorm_ar` 自定义内核，在 MI355X 上提升输出吞吐 14.7%。  
- **#45000**（已合并）：修复 GDN KKT 预热回归（RDNA GPU 上因 `tl.dot` 误用 fp32 导致预热时间从 ~150s 暴涨至 ~2400s），仅修改 RDNA 路径，精度验证通过。  
- **#48519**（新增 PR）：优化 DeepSeek-V4 在 ROCm 上的稀疏注意力预填 Kernel，通过调整 `num_warps`、移除冗余 mask、预取下一 tile，吞吐翻倍，TTFT 降低约 10%。  

#### 3. 分布式推理修复

### 💬 高热度讨论分析

#### 1. Issue #48503 — Gemma 4 MTP 在 CUDA Graph 捕获中崩溃
- **核心议题**：`_suppress_token_ids` 是 Python list 而非 device tensor，导致在 CUDA Graph 捕获期间隐式 H2D 复制错误。  
- **观点与过程**：  
  - `cert4u`（提交者）提供了清晰根因与修复建议（在 `__init__` 中转为 device tensor）。  
  - `ErenAta16` 打开 #48509，使用 `register_buffer` 而非 `self.device` 属性，因类在 `__init__` 时无 device 属性。  
  - `pranavthakur0-0` 测试后发现 `logits[:, ids] = -float('inf')` 仍会在捕获时触发 H2D 复制（标量赋值问题），建议改用 `index_fill_`；同时发现 `gemma4_mm.py` 和 `gemma4_unified.py` 也存在相同模式，提交 #48515。  
  - `ErenAta16` 认可并关闭 #48509，转向 #48515。  
- **争议焦点**：无原则分歧，技术细节在于 `register_buffer` 与 `self.device` 的选择、标量赋值路径的隐性 H2D 问题。  
- **当前状态**：修复方案已明确，PR #48515 待合并。

#### 2. PR #48522 — Gemma4 终止 token 泄漏到输出内容中
- **核心议题**：流式推理时 Gemma4 的结束标记（如 ``）可能因 detokenizer 刷新顺序泄漏到 `content` 字段。  
- **观点**：  
  - 提交者 `rathodkunj2005` 提供了修复方案——将 turn-end 和 EOS sentinel 注册为显式解析器终端，并丢弃。  
  - 评审者 `bbrowning` 质疑描述的场景（detokenizer 在 token id 之前刷新文本）在真实的 vLLM 流式路径中不可能发生，要求提供真实复现示例。  
  - 提交者无法提供真实模型复现，承认测试构造的顺序 vLLM 不会产生，主动关闭 PR。  
- **争议焦点**：修复基于对内部机制的可能误解；评审要求实际证据。  
- **当前状态**：PR 已关闭，未合并。

#### 3. Issue #48492 — MTP 模型中 `eh_proj` 层量化配置缺失导致精度损失
- **核心议题**：7 个 MTP 模型的 `eh_proj` 使用 `nn.Linear` 而非 `ReplicatedLinear` with `quant_config`，导致 W8A8 量化下 INT8 权重被当作 BF16 加载而未被反量化，虽因后接 RMSNorm 掩盖异常但精度严重损失。  
- **观点**：  
  - `tubaii`（提交者）提供了详尽的 dump 分析，指出 RMSNorm 掩盖了 1116 倍放大。  
  - `ErenAta16` 提交修复 PR #48506，同时指出 `ReplicatedLinear` 返回 `(output, bias)` 元组，需同时修改调用处。  
- **争议焦点**：原始 issue 中只建议改层定义，PR 作者指出必须同时修改调用处。  
- **当前状态**：PR #48506 待合并。

#### 4. PR #48505 — DeepSeek V4 的 MXFP4 专家缓存支持
- **核心议题**：为 `--moe-expert-cache-size` 添加 MXFP4 量化专家缓存支持，使 DeepSeek V4 能在显存受限的节点上运行。  
- **讨论要点**：  
  - 需将默认的大一统（monolithic）MXFP4 内核切换到模块化内核（如 `OAITritonExperts`），实现专家 ID 到槽位的映射。  
  - 涉及 17 个文件 +1136/-57 行，CI 显示合并冲突需 rebase。  
  - 评审尚未深入，作者 `jlamweil` 正在处理冲突。  
- **当前状态**：PR 开放，待 rebase 后继续。

#### 5. Issue #48493 — MiniMax-M3 INT4 量化因 `clamp_limit` 缺失阻塞
- **核心议题**：W4A16 (GPTQ/AWQ) 在 `SWIGLUOAI_UNINTERLEAVE` 激活格式下因 `FusedMoEQuantConfig` 未传入 `swiglu_limit`（应为 7.0）失败。  
- **观点**：  
  - `rathodkunj2005` 追踪到 `CompressedTensorsWNA16MarlinMoEMethod` 构建时缺少该参数，提供了修补分支并通过无 GPU 回归测试。  
  - 请求社区用真实模型验证后合并。  
- **当前状态**：待验证，PR 未提交。

   - 从 #48440 禁用、到 #48526 在 ROCm 上以正确方式重新启用，体现了 CUDA Graph 在非 NVIDIA 平台上的复杂性与工程取舍。ROCm 侧对稀疏注意力、MLA、Mamba 等新算子的适配加速。

   - 大量 PR 涉及 KV 缓存释放顺序（#48489）、MoRIIO 读取完成屏障（#48534）、L2 缓存污染导致性能下降（#48518）等，显示大规模部署前系统级稳定性仍是重点。
